Latar Belakang

Latar Belakang Project

Saat ini data siswa dan kelas masih dicatat manual di buku atau spreadsheet terpisah. Cara ini lambat, mudah duplikat, dan sulit dipakai saat menyusun laporan.

Karena setiap siswa selalu terhubung ke satu kelas, pencatatan terpisah membuat data cepat tidak sinkron. Sekolah butuh satu tempat yang rapi untuk mencatat, mencari, dan memperbarui data.

Karena itu dibuat aplikasi web sederhana berbasis Laravel untuk mengelola data siswa & kelas secara terpusat, sesuai kebutuhan PRD dan kompetensi yang dipelajari.

💡
Pelajaran: Sebelum menulis kode, pahami dulu masalah nyata dan alasan project ini dibuat.

Step 1

Pahami Kebutuhan Project

  • Kelola data siswa dan data kelas.
  • Setiap siswa terhubung dengan satu kelas.
  • Menerapkan CRUD: Create, Read, Update, Delete.
  • Dibatasi dua tabel sesuai PRD.

Fitur wajib

  • Tambah, lihat, edit, hapus siswa.
  • Tambah dan lihat kelas.
  • Pilih kelas saat input siswa.
  • NIS unik, nama & kelas wajib.

Belum dibuat

  • Login.
  • Nilai & absensi.
  • Upload foto.
  • Search & export CSV.

Step 6 · Tabel Kelas

Migration: Tabel Kelas

Buat file migration lalu isi schema tabel kelas.

Setiap blok code bisa disalin lewat tombol clipboard di pojok kanan.

1. Generate file migration

php artisan make:migration create_kelas_table

2. Copy schema tabel kelas — database/migrations/2026_09_08_000001_create_kelas_table.php

<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up()
    {
        Schema::create('kelas', function (Blueprint $table) {
            $table->id();
            $table->string('nama_kelas')->unique();
            $table->timestamps();
        });
    }

    public function down()
    {
        Schema::dropIfExists('kelas');
    }
};
💡
Pelajaran: nama_kelas dibuat unik agar tidak ada nama kelas yang kembar.
🧱

Step 6 · Tabel Siswa

Migration: Tabel Siswa

Buat file migration lalu isi schema tabel siswa, terhubung ke tabel kelas.

Setiap blok code bisa disalin lewat tombol clipboard di pojok kanan.

1. Generate file migration

php artisan make:migration create_siswa_table

2. Copy schema tabel siswa — database/migrations/2026_09_08_000002_create_siswa_table.php

<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up()
    {
        Schema::create('siswa', function (Blueprint $table) {
            $table->id();
            $table->string('nis')->unique();
            $table->string('nama');
            $table->foreignId('kelas_id')
                ->constrained('kelas')->cascadeOnDelete();
            $table->enum('jenis_kelamin', ['L', 'P'])->nullable();
            $table->timestamps();
        });
    }

    public function down()
    {
        Schema::dropIfExists('siswa');
    }
};

3. Jalankan migration

php artisan migrate
php artisan migrate:fresh   # hapus & buat ulang semua tabel (development)
💡
Pelajaran: Migration adalah version control untuk struktur database.

Step 7 · Model Siswa

Model Siswa

Model Siswa punya relasi belongsTo ke Kelas.

Setiap blok code bisa disalin lewat tombol clipboard di pojok kanan.

2. Copy code model Siswa — app/Models/Siswa.php

<?php
namespace App\Models;
use Illuminate\Database\Eloquent\Model;

class Siswa extends Model
{
    protected $table = 'siswa';
    protected $fillable = ['nis', 'nama', 'kelas_id', 'jenis_kelamin'];

    public function kelas()
    {
        return $this->belongsTo(Kelas::class);
    }
}

Step 8 · validated()

validated() — Aturan Validasi

Aturan validasi bersama untuk store() dan update(). Baris terakhir menutup class.

private function validated(Request $request, ?Siswa $siswa = null)
{
    return $request->validate([
        'nis' => ['required', 'string', 'max:50', Rule::unique('siswa', 'nis')->ignore($siswa)],
        'nama' => ['required', 'string', 'max:255'],
        'kelas_id' => ['required', 'integer', 'exists:kelas,id'],
        'jenis_kelamin' => ['nullable', Rule::in(['L', 'P'])],
    ]);
}
}

Step 9 · destroy()

destroy() — Hapus Kelas

Menolak hapus jika kelas masih punya siswa; jika kosong, kelas dihapus. Baris terakhir menutup class.

public function destroy(Kelas $kela)
{
    if ($kela->siswa()->exists()) {
        return redirect()->route('kelas.index')
            ->with('error', 'Kelas tidak dapat dihapus karena masih memiliki siswa.');
    }
    $kela->delete();
    return redirect()->route('kelas.index')->with('success', 'Kelas berhasil dihapus.');
}
}

Styling · Struktur

CSS Terpisah per Halaman

Satu file dasar app.css dipakai semua halaman, lalu setiap halaman punya file CSS sendiri. File tidak menumpuk, mudah dicari, dan mudah dirawat.

Setiap blok code bisa disalin lewat tombol clipboard di pojok kanan.

Struktur folderDasar + satu file untuk tiap halaman.
public/css/
├── app.css            dasar: navbar, card, tombol, tabel, form
├── siswa/
│   ├── index.css
│   ├── create.css
│   ├── edit.css
│   └── show.css
└── kelas/
    ├── index.css
    ├── create.css
    ├── edit.css
    └── show.css
MenghubungkanSlot @stack di layout, diisi @push dari tiap halaman.
{{-- layouts/app.blade.php --}}
<link rel="stylesheet" href="{{ asset('css/app.css') }}">
@stack('styles')

{{-- siswa/index.blade.php --}}
@push('styles')
    <link rel="stylesheet" href="{{ asset('css/siswa/index.css') }}">
@endpush

Pelajaran: @stack('styles') menyiapkan tempat di layout, @push('styles') mengisi tempat itu dari tiap halaman.

Step 15B · Register

Register — Simpan Admin Baru

Controller AdminAuthController — password disimpan dalam bentuk hash.

php artisan make:controller AdminAuthController
use App\Models\Admin;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Hash;

public function register(Request $request)
{
    $request->validate([
        'username' => ['required', 'string', 'max:50', 'unique:admin,username'],
        'email' => ['required', 'email', 'max:255', 'unique:admin,email'],
        'password' => ['required', 'string', 'min:6'],
    ]);

    Admin::create([
        'username' => $request->username,
        'email' => $request->email,
        'password' => Hash::make($request->password),
    ]);

    return redirect()->route('admin.login')->with('success', 'Akun admin berhasil dibuat, silakan login.');
}
💡
Pelajaran: Hash::make() mengubah password menjadi hash satu arah — password asli tidak pernah disimpan di database.

Step 15B · Login

Login — Cek dengan if Manual

Tidak memakai Auth::attempt(). Kita cari admin, cek password dengan Hash::check(), lalu simpan token ke cookie.

public function login(Request $request)
{
    $admin = Admin::where('username', $request->username)->first();

    if (! $admin) {
        return back()->with('error', 'Username tidak ditemukan.');
    }

    if (! Hash::check($request->password, $admin->password)) {
        return back()->with('error', 'Password salah.');
    }

    $token = hash('sha256', $admin->email);

    return redirect()->route('admin.dashboard')
        ->with('success', 'Login berhasil.')
        ->withCookie(cookie('admin_token', $token, 120));
}
💡
Pelajaran: Hash::check() membandingkan password yang diketik dengan hash di database tanpa membalik hash-nya.

Step 15B · Middleware

Middleware AdminAuth

Cek cookie token di setiap request. Token dianggap sah jika hash('sha256', email) cocok dengan email admin di database.

php artisan make:middleware AdminAuth
<?php

namespace App\Http\Middleware;

use App\Models\Admin;
use Closure;

class AdminAuth
{
    public function handle($request, Closure $next)
    {
        $token = $request->cookie('admin_token');

        if (! $token) {
            return redirect()->route('admin.login')->with('error', 'Silakan login terlebih dahulu.');
        }

        $cocok = Admin::all()->contains(function ($admin) use ($token) {
            return hash('sha256', $admin->email) === $token;
        });

        if (! $cocok) {
            return redirect()->route('admin.login')->with('error', 'Sesi tidak valid, silakan login ulang.');
        }

        return $next($request);
    }
}
💡
Pelajaran: Middleware berjalan sebelum halaman dibuka, jadi halaman terkunci tidak pernah sempat tampil.

public function update(Request $request, Admin $admin)
{
    $request->validate([
        'username' => ['required', 'string', 'max:50', Rule::unique('admin', 'username')->ignore($admin)],
        'email' => ['required', 'email', 'max:255', Rule::unique('admin', 'email')->ignore($admin)],
        'password' => ['nullable', 'string', 'min:6'],
    ]);

    $data = $request->only('username', 'email');

    if ($request->filled('password')) {
        $data['password'] = Hash::make($request->password);
    }

    $admin->update($data);

    return redirect()->route('admin.dashboard')->with('success', 'Data admin berhasil diperbarui.');
}

Fungsi · Fitur Admin

Alur Autentikasi Manual

  • Hash::make() — password disimpan sebagai hash, bukan teks asli.
  • Hash::check() — mencocokkan password yang diketik dengan hash di database.
  • hash('sha256', $admin->email) — token yang disimpan di cookie admin_token.
  • $request->cookie('admin_token') — membaca token di middleware setiap request.
  • Middleware admin — membandingkan token cookie dengan email admin di database.

Kenapa di-hash dua kali?

Password di-hash agar aman. Email di-hash hanya untuk dijadikan token rahasia, sehingga email asli tidak tampil di cookie.

Alur singkat

Register → Login → Cookie token dibuat → Setiap pindah halaman dicek middleware → Logout hapus cookie.

💡
Pelajaran: Autentikasi manual ini memperlihatkan cara kerja login, cookie, dan middleware di balik layar.
